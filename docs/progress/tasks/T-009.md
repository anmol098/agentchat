# T-009 — Licence boundary enforcement

The repository is split-licensed: `packages/` is MIT and `server/` is AGPL-3.0-or-later. MIT code may be absorbed into an AGPL work, but never the reverse, so the dependency direction is a legal boundary rather than an architectural preference. A single import from `packages/` into `server/` would silently relicense the permissive half of the project. This check makes that mistake impossible to merge.

## Acceptance criteria

- [ ] A script fails when any file under `packages/` imports, requires, or re-exports anything under `server/`, including through a path alias or a dynamic import.
- [ ] The check covers the workspace dependency graph as well as source imports, so a package manifest cannot introduce the dependency either.
- [ ] Every package manifest declares the correct `license` field, and a mismatch with the path is an error.
- [ ] A dependency added under `packages/` whose licence is not permissive (MIT, ISC, BSD, or Apache-2.0) fails the check.
- [ ] Failure messages explain the licensing consequence, not just the rule, so the next contributor understands why it matters.
- [ ] The check runs in continuous integration on every pull request.
