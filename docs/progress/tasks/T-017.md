# T-017 — A distinct error code for an unreachable server

The frozen error set has no code for "could not reach the server". The client currently reports a transport failure as `INTERNAL`, the same code a server uses when it faulted, and distinguishes the two only by JavaScript class.

A class check is invisible to a `--json` consumer, and those consumers are the point of this project: an agent harness reading structured output cannot tell "the network is down, retry" from "the server broke, do not retry". Those call for opposite actions, which is exactly the admission test the frozen set applies.

## Acceptance criteria

- [x] A decision on whether to add a code, argued against the set's own admission test rather than by preference.
- [x] If added, the client uses it for transport failures and `INTERNAL` stops being overloaded.
- [x] The distinction is visible in `--json` output, not only through a class check.
- [x] The protocol snapshot check is satisfied. Adding a code is additive, so this should pass without a version bump; confirm that rather than assuming it.
- [x] Client tests cover a connection refusal, a timeout, and a server-side 500, and assert the codes differ.

## Notes

Raised by T-202 while building the client, which could not add the code itself because the protocol package was outside its paths.

Consider whether a timeout and a refused connection deserve one code or two. One is probably right, but say why.

Read T-013 before starting. It settled where operational concerns sit relative to the frozen set, and its reasoning applies here in the opposite direction: this one clients genuinely branch on.
