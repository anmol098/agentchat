# T-021 — Export the CLI modules from the package barrel

Three tasks each built a module the command tasks need, and none of them added an export line, because `packages/cli/src/index.ts` belonged to none of them and all three were running at once. The credential store, the context resolver and the configuration reader are all reachable only by relative import.

That is fine inside the package and wrong at its edge. Every command task after this one will either add the export itself, creating the collision the path rule exists to prevent, or quietly import around the barrel and leave the package with no coherent public surface.

## Acceptance criteria

- [ ] The credential store, context resolution, and user and repository configuration are exported from the package barrel.
- [ ] What is exported is deliberate: the barrel is the package's public surface, so internal helpers stay internal. Say what you excluded and why.
- [ ] Existing relative imports inside the package still work, or are updated consistently. Do not leave two idioms in one package.
- [ ] Nothing about the CLI's behaviour changes; this is surface, not function.

## Notes

Raised independently by T-204 and T-205, both of which named the exact export line they would have added.

Small, but worth doing before the command tasks land rather than after, because each of them would otherwise have a reason to touch this file.
