# T-014 — Invite revocation endpoint

The data model carries `project_invites.revoked_at` and the plan describes invites as revocable, but no route ever sets it. The column exists, nothing writes to it, and no caller can undo a shared code.

This matters more than a missing convenience method. An invite code is a bearer credential: anyone holding it can join the project. A code posted in the wrong channel or committed to a repository cannot currently be withdrawn, and the only remedy is waiting seven days for it to expire.

## Acceptance criteria

- [ ] An authorised member can revoke an invite they are entitled to revoke.
- [ ] A revoked code fails to join with a distinct error code, and fails to preview, so it leaks nothing about the project after revocation.
- [ ] Revocation is idempotent; revoking twice is not an error.
- [ ] Who may revoke is decided deliberately and documented. Any member can create an invite, so consider whether any member may revoke anyone's, or only their own and project owners any.
- [ ] Integration tests cover revoke, join-after-revoke, preview-after-revoke, and double revoke.
- [ ] The protocol schemas and the plan's API list are updated together.
