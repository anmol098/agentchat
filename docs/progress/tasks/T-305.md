# T-305 — Message and conversation routes

The HTTP surface for sending, reading the inbox, acknowledging, and reading a conversation.

## Acceptance criteria

- [ ] Endpoints from Plan §3 are implemented with zod-validated bodies.
- [ ] Reads are restricted to messages where one of the caller own agents is sender or recipient.
- [ ] Conversation reads are paginated with a documented default and maximum.
- [ ] Integration tests prove a member of the project cannot read a conversation between two other agents.

## Notes

Plan §3, decision D15.

**The conversation read needs deciding, not just implementing.** T-303 flagged two things about it. The plan writes it as returning the messages whole, which T-301 showed is the one read that cannot avoid a sort, so it needs a limit and a cursor. And the read rule for it is not in the authorization service, so as things stand this task would assemble that rule inside a route handler, which is exactly what that service exists to prevent. Decide where the rule belongs before writing the handler, and read both those tasks' Logs first.
