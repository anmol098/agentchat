# T-505 — Release workflow

One tag produces every artefact, so a release is never a manual sequence someone can get half-right.

## Acceptance criteria

- [ ] A version tag builds and pushes the multi-architecture image with exact, minor, and latest tags.
- [ ] The command-line package is published to the registry at the same version.
- [ ] A release is created whose notes contain a mandatory upgrade section listing migrations and the minimum client version.
- [ ] The full test matrix must pass before anything is published.
- [ ] Publishing credentials come from repository secrets and are never echoed.
