# T-026 — Resolve the server URL once, and give a fresh install somewhere to point

Two problems, one cause.

**Nothing supplies a server URL.** On a clean machine every networked command fails because there is no default and nothing writes one. `agentchat whoami` answers "run login with --server", which means a new user must already know the address of a server before the tool can help them find one. For a project where hosting is the user's choice a hardcoded default may well be wrong, but silence is worse than a documented default with a way to override it.

**The resolution logic is about to be duplicated.** The authentication commands resolve the URL from a flag, then an environment variable, then user config. Every networked command needs the same three steps, and the second copy is where they start to disagree. This is the same shape as the duplicated config-directory computation in T-024, caught before rather than after.

## Acceptance criteria

- [ ] One shared resolver, used by the authentication commands and available to every later command.
- [ ] A fresh install has a usable path to a server: either a documented default, or a first-run flow that records one, or a failure message that tells the user exactly what to do rather than naming a flag.
- [ ] Whatever is chosen is written down in the plan, because a self-hoster needs to know what their users will point at.
- [ ] Tests cover each step of the resolution order and the fresh-install case.

## Notes

Raised by T-206, which implemented the resolution privately and said plainly that the second implementation should become the shared one rather than a copy.
