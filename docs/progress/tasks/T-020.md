# T-020 — A rate-limit error code

The frozen error set has no code meaning "you are going too fast, wait and retry". The device-flow poll endpoint needs one: when the provider answers `slow_down`, the client must keep polling more slowly, which is different from both "keep polling at the same rate" and "stop".

Lacking a code, the poll endpoint returns `CONFLICT`, chosen only because it is the one remaining code a client can tell apart from the other two outcomes. Its documented meaning has nothing to do with rate limiting, so the next reader of that mapping will be misled.

## Acceptance criteria

- [x] A decision, argued against the frozen set's own admission test: would a caller take a different action on it? Here the answer looks like yes, since the correct response is to wait and retry rather than to fail or continue unchanged.
- [ ] If added, the poll endpoint uses it and `CONFLICT` returns to meaning what it says. **Not met, deliberately.** `server/src/routes/auth.ts` and `packages/cli/src/commands/auth.ts` are both outside this task's paths and have to change together; see the Log. `docs/protocol.md` section 13 records the gap so the document is not lying in the meantime.
- [x] The snapshot check passes. Adding a code is additive under the compatibility rule, so this should need no version bump; confirm rather than assume.
- [x] Whether the code carries retry timing, or whether that stays in a header, is decided and documented.

## Notes

Raised by T-103, which could not add it: the protocol package was outside its paths and minting a code is a change to a public contract, not a local convenience.

Read T-013 first. It settled how this project decides what belongs in the frozen set, and the reasoning applies here in the direction of admitting one.
