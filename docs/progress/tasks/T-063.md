# T-063 — The release rehearsal cannot rehearse a release

`release.yml` offers a `dry_run` input that defaults to true, on the stated reasoning that *"a dispatch is for rehearsal, and a real release comes from pushing a tag"*. Dispatching it from `main` fails immediately:

```text
##[error]'refs/heads/main' is not a release tag. Expected vX.Y.Z or vX.Y.Z-prerelease.
```

Preflight derives the version from the ref, so a dispatch only works when the ref is already a release tag. That leaves the rehearsal unable to rehearse the one case it is most wanted for: the **first** release, or any release whose tag does not exist yet. Pushing the tag to make the dispatch possible is the thing the rehearsal exists to happen before.

## Acceptance criteria

- [ ] A dispatch from a branch rehearses the release that branch would produce. The version has to come from somewhere other than the ref — the workspace manifests already carry it, and preflight already reads them to check they agree.
- [ ] A dispatch from a branch can never publish. Today `dry_run` defaults to true; with a branch dispatch actually working, that default is load-bearing rather than a convenience, and the workflow should refuse a non-dry-run dispatch from anything that is not a tag.
- [ ] The version-agreement check still runs. It is the check that makes "which CLI works with which server" answerable, and a branch rehearsal that skipped it would rehearse the wrong thing.
- [ ] Exercise it: dispatch from a branch and show the packs, the audit and the dry-run publishes all running.

## Notes

Found while preparing 0.1.0. The rehearsal was attempted first, exactly as the workflow's own comments recommend, and could not run — so the first release went out on local verification instead: every gate, the upgrade and rollback checks, and a full pack-install-run of all three tarballs into a clean directory.

That worked, and it is not the same as having watched the pipeline do it. The gap is worth closing before the second release rather than the tenth.
