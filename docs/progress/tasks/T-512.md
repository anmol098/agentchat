# T-512 — There is no installable Skill for agentchat, only a hook-wired example

`examples/claude-code/` gets an agent listening by wiring hooks into
`.claude/settings.json` — push-based, and specific to one harness's session
lifecycle. Skills (SKILL.md plus a directory, in the Anthropic Claude Code /
Claude.ai sense) are a different, pull-based mechanism: a harness lists an
agent's available skills by name and one-line description, and the agent
consults one on demand when a request matches. Several harnesses that speak
AgentChat's real audience (agents needing to message each other) can install a
Skill; none of them can install a hook script written for Claude Code's
`settings.json` shape.

There is currently no packaged Skill in this repository at all, so an agent
that wants to use `agentchat` idiomatically — read the right identifiers,
thread replies, ack only after acting, never assemble an address — has to
reconstruct that from `docs/cli.md` and `examples/README.md` every time, or a
maintainer has to hand-copy the equivalent instructions into the agent's own
context file.

## Acceptance criteria

- [ ] `skills/agentchat/SKILL.md` exists with valid frontmatter (`name`,
      `description`) and instructs an agent through the actual minimum loop:
      discover peers (`agentchat agents --json`, address is a lookup key,
      never assembled), read (`inbox` vs `listen`, and when each applies),
      reply threaded (`--conversation` / `--reply-to`), and ack only after
      acting.
- [ ] It is self-contained: no relative link into this repository's own
      `docs/`, since a Skill is meant to be copied out and installed
      elsewhere, in a repository that will not have `docs/cli.md` alongside
      it.
- [ ] It restates, rather than assumes, the two things this project has
      already learned cost people time: the two message shapes differ
      (`listen` vs `inbox`/`conversation`) in exactly which fields are absent
      vs. `null`, and exit codes 2/3/4 each have a specific automatable
      remedy.
- [ ] `skills/README.md` explains what a Skill is for a reader who may not
      know the term, and how to install it (copy the directory into
      `.claude/skills/` or wherever the target harness looks).
- [ ] The description field is written to trigger on intent ("message the
      other agent", "check my inbox", "who's online") and not only on the
      word "agentchat", since a user asking a harness to talk to a teammate's
      agent will rarely name the transport.

## Notes

PRD invariant 7/8 (the server does not interpret content; the agent decides
what a message means) governs the Skill's content the same way it governs
`examples/`: no message-type table, no keyword rule, nothing that would
quietly reintroduce a schema on the reading end that the wire protocol
deliberately does not have.

This does not touch `examples/claude-code/`; that hook wiring is still the
right answer for "start a listener automatically for the life of a session,"
which a pull-based Skill does not replace.

`README.md`'s "Wire it into your agent" table and MIT-parts sentence should
gain a row/mention for `skills/` too, but `README.md` is claimed by T-073
(in_review) as this is filed. Follow up once that lands rather than blocking
on it or widening this task's scope into a file another task owns.
