# T-015 — Wire the server to the protocol package and stop emitting off-contract error codes

The server cannot import `@agentchat/protocol`. There is no dependency in its manifest and no project reference in its TypeScript configuration. Everything below follows from that.

Because it cannot import the frozen error codes, `app.ts` hardcodes them as string literals, and they have already drifted:

- The 500 handler emits `INTERNAL_ERROR`. The frozen set contains `INTERNAL`. The server is emitting a code no client can find in the contract.
- `NOT_FOUND` and `BAD_REQUEST` are written as literals, so nothing catches the next typo either.
- The 4xx path passes Fastify's own `error.code` straight through to the client. That is not reachable today only because no route accepts a body; the moment one does, a wrong content-type returns a framework-internal string where the contract promises a stable code.

These responses are the protocol envelope on protocol routes, so this is the exact drift the frozen set exists to prevent, sitting in the one file every future route inherits from.

## Acceptance criteria

- [ ] The server depends on `@agentchat/protocol` in its manifest and references it from its TypeScript project, and the licence boundary check still passes (the server may depend on packages; never the reverse).
- [ ] Every error code the server emits comes from the frozen set. No string literals.
- [ ] `INTERNAL_ERROR` is corrected to `INTERNAL`.
- [ ] A framework error code can never reach a client. Map what is known and fall back to a contract code, rather than passing an unknown string through.
- [ ] A test proves an off-contract code cannot escape, ideally by asserting every error response's code against the frozen set rather than by listing cases.
- [ ] The health endpoint keeps its deliberately separate operational code; see T-013 for why that is not a violation.

## Notes

Found during T-013 by reading rather than by a failing test, which is worth noting: nothing in the current suite would have caught it.

This blocks the milestone 1 route tasks. Each of them will copy whatever `app.ts` does, so the literals must be gone before they multiply.

The protocol package exports `ErrorCodeSchema` as a strict outbound assertion. Consider using it as the enforcement mechanism rather than reviewer discipline.
