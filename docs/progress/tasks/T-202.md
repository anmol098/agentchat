# T-202 — HTTP client and credential store interface

The typed client both the CLI and any future integration use. Handles authentication headers, token refresh, and error translation, and defines the transport seam a daemon can later slot into.

## Acceptance criteria

- [ ] A `Transport` interface abstracts request and connect, with a direct HTTP implementation for v0.1.
- [ ] A 401 triggers exactly one refresh and one retry before surfacing an authentication-required error.
- [ ] A `CredentialStore` interface is defined here with no filesystem access in this package.
- [ ] Server error envelopes become typed client errors that preserve the stable code.
- [ ] Requests carry the client version header.
- [ ] Unit tests against a mock server cover refresh, retry, and error translation.
