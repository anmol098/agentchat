# T-516 — Release 0.3.0, so the skill and its auto-install ship

T-512 through T-515 are on `main` and in no release: `skills/agentchat/`, its
discoverability via skills.sh (badge, install instructions), and the
`postinstall` script that installs it automatically on
`npm install --global @anmol098/agentchat`. None of it is reachable by a real
user until it ships.

This is a **minor**, not a patch: new, backward-compatible capability (the
Skill and the auto-install behaviour), not a bug fix. Nothing in it touches
the wire protocol or the schema — `PROTOCOL_VERSION` stays `5` and
`MIN_CLIENT_VERSION` stays `0.1.0`, exactly as for T-073's patch release,
because an old client and a new server (or the reverse) still agree on
everything the wire actually carries.

## Acceptance criteria

- [ ] Every pinned version reads 0.3.0: the five manifests, `CLI_VERSION`,
      `SERVER_VERSION`, `packages/cli/tests/binary.test.ts`'s expected
      version, the example environment file, and every document that names
      the current release as a live pin (README.md, CONTRIBUTING.md,
      deploy/compose/README.md, docs/self-hosting.md, docs/upgrading.md,
      docs/system-design.md, docs/cli.md, docs/protocol.md). A version number
      inside a **historical** sentence — e.g. docs/system-design.md's "until
      release 0.2.1 nothing on the socket path refreshed the row" — describes
      the past and does not change.
- [ ] The release rehearsed from the task branch with a dry-run dispatch
      before the tag exists, and every job passed.
- [ ] `v0.3.0` tagged on `main` after the bump merges; the release workflow
      publishes the image, the three packages, and the GitHub Release with
      upgrade notes (no migration, protocol version unchanged).
- [ ] The upgrade workflow on `main` stays green after the release.
- [ ] `docs/progress/release-readiness.md` gets a new dated log entry once
      the release is actually out, the same way it recorded 0.2.1 — appended
      directly to `main` after publishing succeeds, not as part of the
      version-bump pull request, since it describes something that has not
      happened yet until the tag is live.
