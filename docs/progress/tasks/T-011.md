# T-011 — Test against every supported Node version

The workspace declares `node >= 22.12` and the implementation plan names both the 22 and 24 long-term-support lines. Continuous integration tests only Node 24, so a change that breaks Node 22 would pass every gate and ship.

That gap matters more than usual here: this project asks strangers to self-host a server, and the Node version they run is their choice, not ours.

## Acceptance criteria

- [ ] The unit and integration jobs run as a matrix over the supported Node versions, at minimum 22 and 24.
- [ ] The fan-in job requires every matrix leg, so a failure on either version blocks the merge.
- [ ] Job naming stays predictable, and the pull request states which check names branch protection should require after the change.
- [ ] A change that works on one version and not the other is demonstrably caught. Show the evidence.

## Notes

Raised by T-004, which deliberately deferred this: matrix jobs change the check names, and that task existed to establish stable ones first. Read its Log before starting.

Consider whether the lint and format job needs a matrix at all. Biome does not vary by Node version, so running it once is probably right; say which you chose and why.
