# T-105 — Authentication plugin and error envelope

Cross-cutting request handling: bearer token verification, the typed application error hierarchy, and a single error formatter so every failure looks the same on the wire.

## Acceptance criteria

- [ ] A Fastify decorator exposes the authenticated user to handlers, and unauthenticated requests to protected routes get 401 with a stable code.
- [ ] Typed errors carry an HTTP status and a stable `code` from the protocol package.
- [ ] The error handler never leaks a stack trace, a SQL fragment, or a driver message to the client.
- [ ] Unexpected errors are logged in full with the request ID and returned as a generic 500.
- [ ] Tests assert the envelope shape for 400, 401, 403, 404, and 500.

## Notes

Plan section 3, Protocol section 7.3. Stable codes are a public contract; changing one is a breaking change.
