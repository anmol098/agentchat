# T-054 — A socket reset during a token refresh kills the listener outright

`agentchat listen` exits with an uncaught exception when a connection is accepted and then reset while it is refreshing its access token:

```text
setTypeOfService EINVAL
```

undici raises it from a socket event rather than from the awaited request, so it lands outside the `catch` in the client's refresh path — the `catch` that exists for precisely this case, "the server is unreachable". An unhandled exception takes the process down, and the whole point of the listener is that it does not go down.

Reproduced on every run by T-509's chaos suite on Node 24.20.0 and macOS, by accepting the connection and then resetting it.

## Acceptance criteria

- [ ] A socket reset at any point in a refresh is handled the way an unreachable server is handled: reported, retried, never fatal.
- [ ] The fix catches the class of problem rather than that one message. An error arriving on a socket event instead of on the awaited promise is the shape to defend against; `EINVAL` from one syscall is a symptom.
- [ ] `SERVER_UNREACHABLE` is the code a `--json` consumer sees, since T-017 added it for exactly this.
- [ ] A regression test that does not depend on the platform. See the note below before writing one.

## Notes

Found by T-509, which **deliberately did not commit a test** for it, and the reasoning is worth keeping: whether that syscall fails on a closed socket is platform-specific, and a test that is red on macOS and green in CI is worse than a written note, because it teaches everyone to ignore a red build. The reproduction is recorded in its module comment and its Log.

So the honest first step is to reproduce it at the level the client actually cares about — an error surfacing on a socket event during an in-flight refresh — rather than to reproduce that syscall.
