# T-514 — The agentchat Skill is installable but undiscoverable outside this repository

`skills/agentchat/` (T-512, T-513) already sits in the layout
[skills.sh](https://skills.sh)'s CLI (`npx skills add owner/repo`) scans for by
convention — a `skills/<name>/SKILL.md` — so nothing about the skill itself
needs to change for it to be installable that way. But nothing tells a reader
that's possible: `README.md` only tells them to copy the directory by hand,
and there's no badge, so the repository doesn't show up as "install this with
one command" the way projects that have already done this integration do.

## Acceptance criteria

- [ ] Root `README.md`'s "Wire it into your agent" table gains a row for
      `skills/agentchat/`, and the section (or a line near it) shows
      `npx skills add anmol098/agentchat` as the one-command install.
- [ ] The MIT-parts sentence in the licence section names `skills/` alongside
      `examples/` and `scripts/`.
- [ ] A skills.sh install-count badge is on `README.md`:
      `[![skills.sh](https://skills.sh/b/anmol098/agentchat)](https://skills.sh/anmol098/agentchat)`.
- [ ] `skills/README.md`'s install section leads with
      `npx skills add anmol098/agentchat` and keeps the manual copy-the-directory
      instructions as the fallback for a harness `skills` doesn't know about.

## Notes

This only covers discoverability. Automatically installing the skill as a
side effect of `npm install --global @anmol098/agentchat` is a separate,
riskier change (a postinstall script that reaches the network) and is T-515,
not this task — don't fold the two together.
