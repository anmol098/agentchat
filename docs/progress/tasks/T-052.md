# T-052 — Move the close-code vocabulary into the shared protocol package

One wire vocabulary is written out twice: `CloseCode` in `server/src/websocket/frames.ts` and `WsCloseCode` in `packages/client/src/websocket/frames.ts`. It has drifted twice, most recently when T-048 added `4429` and the client could not name it.

**The licence boundary is not what forces this.** `packages/protocol` is MIT, both halves already depend on it, and `ErrorCode` lives there shared rather than transcribed twice. Close codes are duplicated only because nobody put them there — and `frames.ts` already says the frame shapes "should eventually live there".

There is a second reason, and it is the stronger one. T-048 found that `pnpm protocol:check` reported the wire contract **unchanged** when it added a close code, because the snapshot covers `packages/protocol` and not the server's enum. A close code that lived in the protocol package would gain the additive-change enforcement it has none of today — the same guard that already refuses a narrowed schema.

T-051 pinned both tables to `docs/protocol.md` §9.6, so they cannot drift silently in the meantime. That is a guard, not a fix: it catches divergence after the fact rather than making divergence impossible.

## Acceptance criteria

- [ ] The close codes live in `packages/protocol`, and both the server and the client take them from there rather than declaring their own.
- [ ] `pnpm protocol:check` covers them, so adding one is judged additive and removing or renumbering one is refused. Confirm by running it, not by assuming.
- [ ] `1001` and `1006` stay on the client side, named as its own small honest split: they are what a browser or a socket library produces, not what this server sends.
- [ ] Nothing under `packages/` imports from `server/`. This task moves code across that boundary and is exactly where it would be broken by accident.
- [ ] T-051's divergence test still passes, or is replaced by something stronger. Do not delete it without a replacement — it is the only thing that has ever caught this.
- [ ] `docs/protocol.md` §9.6 stays the human-readable source of truth and agrees with the shared table.

## Notes

Argued by T-051, which was asked whether a *generated* shared module was warranted and concluded it was not: a generator would add a build step, a checked-in artefact and a stale-file failure mode to solve what an existing shared package solves with none of them. Read its Log for the full reasoning before choosing differently.

Five owners and a frozen-vocabulary decision, which is why it is a task rather than a tidy-up. Read T-013 and T-017 for how this project decides what belongs in a frozen wire vocabulary.

One practical note from T-051: `packages/client` compiles with no Node types on purpose, so `fs` is a compile error there. Any test that reads a file has to live in `packages/client/tests/`, which `tsc` does not cover today. Turning that coverage on needs `rootDir` and `include` changes plus `@types/node` as a devDependency — a decision in files this task does not own, so raise it rather than doing it.
