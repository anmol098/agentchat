# T-043 — The identity, logout and refresh endpoints do not exist

The server registers exactly two authentication routes, both halves of the device flow. Three more are specified, have protocol schemas, have client methods, and are called by shipped commands. None of them exists.

`GET /me`, `POST /auth/logout`, and `POST /auth/refresh` all answer with the unmatched-route response. Verified against a running server.

## What this breaks

Five commands call the identity endpoint: `whoami`, `send`, `listen`, `inbox`, and one more through a shared path. The logout command calls the logout endpoint. Against a real server, all of them fail.

The refresh gap is the worst of the three and is not merely a missing feature. The device flow issues a refresh token that **cannot be spent**, so when the one-hour access token expires the only way back is to run the whole browser authorization again. A listener left running overnight dies and cannot recover on its own, which defeats the durability the rest of the system was built for.

## Why nothing caught it

Every command test uses a stub server that answers these endpoints, so the commands are correct against a server that does not exist. The gap lives exactly between the two suites, which is what an end-to-end test is for, and that suite has not run yet.

## Acceptance criteria

- [ ] All three routes exist and are registered, with the identity and logout routes authenticated and the refresh route reachable without a valid access token, since not having one is the reason to call it.
- [ ] The refresh route spends a refresh token through the existing token service, including its rotation and reuse detection. Do not write a second implementation of that; the service already handles the security-critical part.
- [ ] An integration test proving a listener survives access-token expiry without human intervention. That is the property that matters, not the endpoint's existence.
- [ ] An integration test proving each of the five affected commands works against the real server rather than a stub.
- [ ] A check that a client method cannot exist without a route to call, or a note explaining why that cannot be automated here.

## Notes

Found by T-405 while writing the protocol reference, which is a good argument for writing the document: it forces someone to check that what is described exists.

Read the T-104 Log before touching refresh. Its rotation and reuse detection are deliberate and subtle: presenting an already-rotated token revokes the whole chain, and that revocation commits before the error is raised.
