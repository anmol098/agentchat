# T-047 — Two documents still say the identity endpoints do not exist

`GET /me`, `POST /auth/refresh` and `POST /auth/logout` landed in T-043 and are registered by `registerIdentityRoutes`. Two documents were written while they were missing and still describe that world:

- `docs/self-hosting.md` says this build "serves no endpoint that redeems" a refresh token, and tells an operator their users must re-run `agentchat login` every hour. That was true and is now wrong, and it is wrong in the direction that makes a working deployment look broken.
- `examples/README.md` says the three endpoints "are not implemented on the server yet", pointing at a fix that has since landed.

`docs/protocol.md` was corrected in the same pull request that added the routes, because `server/tests/protocol-doc.test.ts` fails otherwise. These two files have no such check, which is exactly why they drifted.

## Acceptance criteria

- [ ] Both files describe what the server actually serves. Verify against a running server rather than against `docs/protocol.md`, so that a second stale document cannot propagate a third.
- [ ] `docs/self-hosting.md`'s operational advice is corrected, not merely its factual claim. An operator reading it made a plan around hourly re-authentication.
- [ ] Sweep both files for other claims about what this build does or does not serve, and check each. One stale claim of this kind usually has siblings; `GET /version` is genuinely still unserved, so not every such claim is wrong.
- [ ] Record what would have caught this. `docs/protocol.md` has a test and did not drift; these do not and did.
