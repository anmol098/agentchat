# T-047 — Two documents still say the identity endpoints do not exist

`GET /me`, `POST /auth/refresh` and `POST /auth/logout` landed in T-043 and are registered by `registerIdentityRoutes`. Two documents were written while they were missing and still describe that world:

- `docs/self-hosting.md` says this build "serves no endpoint that redeems" a refresh token, and tells an operator their users must re-run `agentchat login` every hour. That was true and is now wrong, and it is wrong in the direction that makes a working deployment look broken.
- `examples/README.md` says the three endpoints "are not implemented on the server yet", pointing at a fix that has since landed.

`docs/protocol.md` was corrected in the same pull request that added the routes, because `server/tests/protocol-doc.test.ts` fails otherwise. These two files have no such check, which is exactly why they drifted.

## Acceptance criteria

- [x] Both files describe what the server actually serves. Verify against a running server rather than against `docs/protocol.md`, so that a second stale document cannot propagate a third.
- [x] `docs/self-hosting.md`'s operational advice is corrected, not merely its factual claim. An operator reading it made a plan around hourly re-authentication.
- [x] Sweep both files for other claims about what this build does or does not serve, and check each. One stale claim of this kind usually has siblings; `GET /version` is genuinely still unserved, so not every such claim is wrong.
- [x] Record what would have caught this. `docs/protocol.md` has a test and did not drift; these do not and did.

## Notes

Found by T-407 while writing the README, which needed to state the same facts and checked them against the code rather than against the neighbouring documents.

Do not extend the protocol-document check to these files as part of this task. That is a larger decision about which documents are load-bearing enough to gate a build on, and it belongs in its own task with an argument.

- 2026-09-09 — The operational correction is bigger than the factual one. Refresh tokens are 32 random bytes stored as a SHA-256 hash and signed with nothing, so now that POST /auth/refresh is served, rotating JWT_SECRET no longer signs anybody out. Proved it: restarted the server under a different secret, watched an access token minted under the old one fail 401, then redeemed a refresh token issued before the rotation for a working pair. Rewrote 'Rotating the signing secret' in both directions — a rotation is now cheap, and it is no longer a way to end a session, which is what an operator reaches for it to do. Ending sessions needs an UPDATE on refresh_tokens, which I ran against the real schema before documenting it.
- 2026-09-09 — Swept both files for sibling claims. GET /version is genuinely still unserved on main today — routes/version.ts defines registerVersionRoutes and app.ts never calls it, and /version sits in PUBLIC_ROUTES so the stamp is never applied and an anonymous caller gets 401 rather than 404. T-041 is in progress on it, so both files now state the caveat as something to check and defer to docs/protocol.md §13 for the list, which is the version of this claim a test keeps honest. Other claims checked and left standing: GitHub is the only identity provider, there is no admin route, there is no rate limit or quota anywhere in server/src, and no route deletes a message.
