# T-106 — Authorization service and permission matrix

Every access rule in the product, in one auditable place. Route handlers ask this service rather than each re-implementing a check.

## Acceptance criteria

- [ ] Assertions exist for project membership, project ownership, agent ownership, and agent participation in a project.
- [ ] Each assertion throws a typed forbidden or not-found error, chosen so the API never reveals the existence of a resource the caller cannot see.
- [ ] Soft-deleted agents fail every assertion.
- [ ] A negative test exists for every rule, proving the disallowed case is actually rejected.

## Notes

Plan §2, PRD §31, Protocol §7.4. Authorization lives in the service layer so a future caller cannot bypass it.
