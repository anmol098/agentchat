# T-515 — Installing the CLI globally doesn't also get you its Skill

Once `npx skills add anmol098/agentchat` is a documented one-command install
(T-514), the maintainer wants the common case — `npm install --global
@anmol098/agentchat` — to do that automatically, so a user who installs the
CLI the way `README.md` already tells them to gets the Skill for whatever
coding-agent harness is on their machine without a second command.

This is a `postinstall` script, which is a real category of risk to get
right: it runs unattended, on every install, and this one would reach the
network (`npx skills add` clones from GitHub). Getting it wrong doesn't just
disappoint someone — it can hang or fail an `npm install` that has nothing to
do with skills, in exactly the offline and CI environments this project has
otherwise been careful to keep working.

## Acceptance criteria

- [ ] `packages/cli` gains a `postinstall` script that runs
      `npx skills add anmol098/agentchat --skill agentchat -g -y` (or the
      equivalent non-interactive invocation) best-effort.
- [ ] **Never fails the parent install.** Every failure mode — `npx`/network
      unavailable, the `skills` package failing to resolve, a non-zero exit,
      a hang — is caught and reported to stderr; the postinstall process
      itself always exits `0`. Bound the child process with a timeout so a
      stalled network call cannot hang `npm install` indefinitely, and give
      it no stdin, so a prompt this can't answer fails fast instead of
      waiting on one.
- [ ] **Only fires for an actual global install of the published package.**
      Guard on `npm_config_global === 'true'` (set by npm and pnpm alike for
      a `-g`/`--global` install, and absent otherwise) so this: (a) never
      runs during this monorepo's own `pnpm install` — packages/cli is a
      workspace member and would otherwise refire this on every contributor's
      install — and (b) never runs when someone adds `@anmol098/agentchat` as
      an ordinary project dependency rather than installing it globally.
- [ ] Respects `CI` (skip; a build pipeline installing the CLI should not
      also reach out to GitHub for a Skill nobody there will use) and a
      documented opt-out, `AGENTCHAT_SKIP_SKILL_INSTALL`.
- [ ] Whatever it does is visible on stderr — what's happening and how to
      turn it off — never a silent background action; see the safety
      standard this whole project already holds itself to for `agentchat`'s
      own stdout/stderr discipline.
- [ ] `docs/cli.md`'s Install section documents the behaviour and the
      opt-out in the same pull request. `README.md` is deliberately left for
      a fast-follow once T-514 (in review as this is filed) merges, the same
      way T-512 deferred its own README wiring around T-073 — not folded in
      here to avoid a path collision with an in-flight PR.
