# T-006 — Local Postgres and Drizzle configuration

Developer-facing database setup: a Compose file for local Postgres and the Drizzle client and migration configuration the server builds on.

## Acceptance criteria

- [ ] `docker compose up -d postgres` gives a working database on a documented port.
- [ ] Postgres image is pinned to a major version.
- [ ] Drizzle config points at `server/drizzle/` for migrations and the schema directory for models.
- [ ] The database client reads `DATABASE_URL`, uses a connection pool, and shuts down cleanly.
- [ ] The `server` workspace member exists with its own manifest and TypeScript configuration extending `tsconfig.base.json`, and `pnpm typecheck` passes with it present.

## Notes

Plan section 1, section 12.2. This is local development only; the deployment stack is T-504.

This is the first task to create anything under `server/`, so it also establishes the workspace member itself. `server/` is AGPL-3.0-or-later, unlike `packages/` which is MIT, so set the manifest `license` field to `AGPL-3.0-or-later` and never import from `server/` into a package.
