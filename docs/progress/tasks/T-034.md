# T-034 — Report runtime metadata in agent discovery

Agent discovery returns each agent with its owner, presence and session count, and nothing about what harness is running it. The product requirements list runtime as information discovery should expose, and today nothing reaches a caller.

It cannot be smuggled in: the route parses its response through a schema that strips unknown keys, so the field has to exist in the contract before the query can carry it.

## Acceptance criteria

- [ ] Distinct runtimes of an agent's active sessions reach a discovery caller.
- [ ] It sits beside presence, never inside the agent. The requirements are explicit that runtime is not identity and that an agent survives changing it, so nesting it under the agent would say the opposite.
- [ ] It folds into the existing single statement. Discovery is one round trip regardless of agent count today, and it must stay that way.
- [ ] **Machine names stay out.** The requirements do not list them, and including them would be the first time a caller learns which host another person's agent runs on. Presence and runtime are about reachability; a hostname is not.
- [ ] The protocol snapshot check is satisfied. Adding an optional field is additive, so this should need no version bump; confirm rather than assume.
- [ ] A test covers an agent with sessions on two different runtimes, and one with none.
