# T-051 — The reference client cannot name the close code the server now sends

T-048 added `CloseCode.BACKLOG_UNREAD = 4429`: the server closes a socket whose peer has stopped reading. `WsCloseCode` in `packages/client/src/websocket/frames.ts` duplicates the server's table and does not know it.

Nothing breaks. An unknown code falls through to `retry` by documented design, which is the right behaviour here. But the reference client cannot *name* what it received, so a consumer built on it sees a number where every other close gives it a case to match on — and `packages/` is MIT precisely so third parties build on it.

The duplication is the underlying issue. Two tables describe one wire vocabulary, and the licence boundary is why: `packages/` may not import from `server/`, so the client cannot simply use the server's enum.

## Acceptance criteria

- [ ] `WsCloseCode` knows `4429` and names it the way the server does.
- [ ] Its disposition is `retry`, matching what the fall-through already does, so no behaviour changes — only the ability to name it.
- [ ] A test that fails if the two tables diverge again. If an honest one cannot be written across the licence boundary, say why, and say what the cheapest alternative is.
- [ ] `docs/protocol.md` section 9.6 is the shared source of truth; check the client against it rather than against the server's enum.
