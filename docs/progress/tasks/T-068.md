# T-068 — The first release left the upgrade gate red and the release notes pointing at a package that does not exist

Two defects surfaced the moment `v0.2.0` existed, and neither could have been seen before it did.

1. **`upgrade.yml` has failed on every push to `main` since the release.** The `from-release` job resolves the previous release with `gh release view --json tagName`, which answers `v0.2.0`, and builds the image reference from that string verbatim. The image is tagged `0.2.0`, without the `v`, so the pull fails with `manifest unknown` and the job that exists to prove the upgrade promise reports that the promise is broken. It is not; the reference is wrong.

2. **The release notes tell users to install a package that does not exist.** The generator writes `npm i -g agentchat@${version}` and lists `agentchat@${version}` under Artefacts, but the package is `@anmol098/agentchat` (T-064). The preflight program already knows the right name as `NPM_PACKAGE_NAME`; the notes program has its own literal.

A third gap is smaller and belongs with these: `deploy/compose/.env.example` pins `AGENTCHAT_VERSION=0.1.0`, a release nobody can run, and nothing checks it. A self-hoster who copies the example gets a version that does not exist, and the example will drift again after every release unless a gate reads it.

## Acceptance criteria

- [ ] `upgrade.yml` strips the leading `v` from the release tag before building the image reference, and the `from-release` job goes green on `main` against the `0.2.0` image.
- [ ] The release notes name the real package in both the install command and the Artefacts table, taken from the same constant preflight uses rather than a second literal.
- [ ] Preflight refuses a tag whose version does not match `AGENTCHAT_VERSION` in `deploy/compose/.env.example`, so the example is always the release it ships with.
- [ ] The `.env.example` fix itself lands with the documentation task that owns `deploy/compose` (T-067).

## Notes

Found during the go-live readiness review on 2026-09-10, the day of the first release. Both are small, and both are the kind of thing only a real release can expose, which is the argument for landing them before the second one.
