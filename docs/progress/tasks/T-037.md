# T-037 — Make the CLI package actually publishable

The package cannot be installed by anyone, and nothing before now would have said so. Four separate problems, all confirmed against main:

- **The name is wrong.** It is `@agentchat/cli`; decision D7 says the binary and the package are both `agentchat`, unscoped, and that name was checked as free.
- **It is marked private**, which is what stops an accidental publish and also stops an intentional one.
- **The versions disagree.** The root is `0.0.0` and the CLI is `0.1.0`, while the plan says one version number spans every package.
- **It depends on two private workspace packages.** When packing, pnpm rewrites the workspace protocol into concrete versions, so the published tarball would name versions of `@agentchat/client` and `@agentchat/protocol` that are not on any registry. Installing it would fail permanently, and no amount of republishing the CLI would fix it.

That last one is the one worth pausing on: the tarball would look fine locally and be broken for every user.

## Acceptance criteria

- [ ] The package publishes as `agentchat`, unscoped, with the binary of the same name.
- [ ] One version number across every package, matching what the release workflow verifies against the tag.
- [ ] The dependency problem solved deliberately. Either publish the client and protocol packages too, which the split licence permits since both are permissive, or bundle them into the CLI's tarball. Say which and why; publishing them makes them a public surface with a compatibility promise, and bundling makes the CLI opaque to anyone who wanted to embed the protocol.
- [ ] The release workflow's preflight passes against the result. It currently reports eight blockers and refuses to build, which is it working.
- [ ] A packed tarball is installed from disk into a clean directory and the binary runs. Do not trust a dry run: it was reported that a dry run did not refuse the private manifest, from either the tarball or the directory.

## Notes

Found by T-505 by building the release pipeline and pointing it at the current tree, which is the only way this class of problem surfaces before a user hits it.

The licence boundary matters here. `packages/` is permissive precisely so third parties can embed the protocol, so bundling it away has a cost beyond convenience. Read the root licence file before choosing.
