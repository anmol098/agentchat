# T-040 — Invite commands

Inviting someone to a project cannot be done from the terminal. The endpoints exist, revocation now exists, and nothing reaches either.

The project commands cover joining with a code, but not minting one and not withdrawing one. So the product's documented onboarding flow, where one person invites another, has no client.

## Acceptance criteria

- [ ] Creating an invite prints the code **and the identifier**. The identifier is disclosed once and never again, and it is what revocation takes, so a caller who does not record it cannot revoke.
- [ ] Revoking by identifier. Note there is deliberately no endpoint that turns a code back into an identifier, so a command taking a code would need one built, which is a disclosure decision rather than a convenience.
- [ ] Both supporting the JSON output mode with a documented shape.
- [ ] The output makes clear the code is a bearer credential: anyone holding it can join, and it works until it expires or is revoked.
- [ ] Tests against a stubbed server.
