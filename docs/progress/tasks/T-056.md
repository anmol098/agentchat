# T-056 — The shipped binary repeats the wrong claim about message shapes

T-046 corrected `docs/cli.md`, which said a streamed `message` event and a listed `inbox` item match field for field. They do not: the streamed shape carries `recipientAgentId` and never a `recipient`, omits `parentMessageId` for a thread root rather than sending `null`, and omits `sender` when the handle cannot be resolved.

**The same claim is compiled into the CLI.** `agentchat inbox --help` prints it today:

> `--json` emits one document carrying `items`, `nextCursor` and `complete`. Each item is the same message shape `agentchat listen --json` emits, so a harness parses one thing.

That is worse than the document being wrong, because a harness author reading `--help` never opens the document. Two more copies exist:

- `packages/cli/src/commands/conversation.ts` repeats it in its own `details:` text.
- `examples/shell/agentchat-bridge.sh` repeats it in a comment. The script itself is correct and never reads `.recipient`, so only the comment misleads.
- `README.md` describes the difference correctly but says `docs/cli.md` "currently claims they match field for field … tracked as T-046", which goes stale the moment T-046 merges.

## Acceptance criteria

- [ ] `agentchat inbox --help` and `agentchat conversation --help` state the difference, and name the fields that are **absent** from the streamed shape rather than only those present. Verify by running the built binary, not by reading the source.
- [ ] Keep it short. Help text is not the reference; point at `docs/cli.md` for the full table rather than reproducing it.
- [ ] The example script's comment matches what the script actually does.
- [ ] `README.md` stops referring to a defect that no longer exists.
- [ ] Check whether any other command's `details:` text makes a claim about a JSON shape, and check each against the code.

## Notes

Found by T-046 while correcting the document, and reported rather than fixed because these files were outside its declared path.

The pattern is worth naming: one wrong sentence was copied into four places, and the copy in the binary is the one users actually read. When a claim about a wire shape appears in help text, it is documentation with no test behind it, which is exactly how `docs/cli.md` came to be wrong three times.

Read T-046's Log for the field-by-field table and for its argument that the difference is **intended** — this task changes prose only, never a shape.
