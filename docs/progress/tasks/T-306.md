# T-306 — WebSocket endpoint and hello handshake

The real-time entry point: authenticate the socket, require a hello frame that binds it to a registered session, and validate every frame against the schema.

## Acceptance criteria

- [ ] The socket authenticates by bearer header, with a query-parameter fallback for clients that cannot set headers.
- [ ] The first frame must be hello; anything else closes the socket with a documented code.
- [ ] Hello validates that the session exists, is active, and belongs to the caller.
- [ ] Unknown frame types and unknown fields are ignored rather than fatal, per the additive-only rule.
- [ ] Malformed JSON and oversize frames close the socket cleanly with a distinct code.
- [ ] Tests cover the handshake, each rejection path, and forward compatibility with an unknown frame.

## Notes

Plan §4.1, §4.2, §12.4. Frame types are transport operations only and must never carry semantics.
