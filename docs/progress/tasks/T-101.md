# T-101 — Schema and migration for users, projects, memberships, invites and refresh tokens

The identity half of the data model. Everything in M1 depends on these tables existing with the right constraints.

## Acceptance criteria

- [ ] Tables for `users`, `projects`, `project_members`, `project_invites`, and `refresh_tokens` match Plan §2.
- [ ] Unique constraints on `users.github_id`, `users.username`, `projects.slug`, and `project_invites.code`.
- [ ] Foreign keys with deliberate cascade behaviour, documented in a comment where a cascade deletes data.
- [ ] The generated migration applies cleanly to an empty database and is idempotent on re-run.
- [ ] Integration test proves each unique constraint rejects a duplicate.

## Notes

Plan §2. Schema tasks are chained by dependency on purpose so two agents never generate migrations concurrently (Protocol §5).
