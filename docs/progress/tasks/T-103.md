# T-103 — GitHub OAuth device flow

The login mechanism. The server brokers the GitHub device flow and upserts a local user, so no password ever exists in this system.

## Acceptance criteria

- [ ] `POST /auth/device/start` returns the user code, verification URI, poll interval, and expiry.
- [ ] `POST /auth/device/poll` returns 428 while pending and tokens on success.
- [ ] Successful authorization upserts the user from the GitHub profile and lowercases the username.
- [ ] GitHub errors including `slow_down`, `expired_token`, and `access_denied` map to distinct stable error codes.
- [ ] The GitHub client secret is never logged or returned.
- [ ] Tests cover the pending, denied, expired, and success paths against a stubbed GitHub.
