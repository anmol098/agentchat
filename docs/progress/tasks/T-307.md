# T-307 — Socket registry and router interface

In-process tracking of which sockets serve which agent and project, behind an interface that a cross-instance implementation can later replace.

## Acceptance criteria

- [ ] Sockets are indexed by the agent and project pair, supporting several sockets per key.
- [ ] A `Router` interface separates "deliver to this agent and project" from how sockets are found, so a Postgres-notify implementation can drop in later.
- [ ] Sockets are removed on close, error, and process shutdown, with no leak under repeated connect and disconnect.
- [ ] Unit tests cover registration, multi-socket fan-out, and cleanup.

## Notes

Plan §4.3, §8. This interface is what unlocks running more than one server instance in v0.2.
