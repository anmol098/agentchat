# T-066 — Give `docs/cli.md` the guard that has kept `docs/protocol.md` honest

Two reference documents, one with a test behind it and one without, and the difference is not subtle:

- `docs/protocol.md` is parsed by `server/tests/protocol-doc.test.ts`, which asserts its endpoint headings against the live route table, its examples against the exported schemas, its error and close-code tables against the frozen sets in both directions, and its quoted constants against the constants. **It has never gone stale.**
- `docs/cli.md` has nothing. It has now been found stale **five times**: a wrong install command, a missing `setup` section, a wrong claim that two message shapes match, a stale protocol version, and a stale agent-name grammar. Three of those were found by tasks that had come to do something else and could not fix it because the file was outside their paths.

The pattern is the argument. Nobody is being careless; the file simply has no mechanism, so it drifts every time a constant or a grammar moves.

## What to build

T-046 sketched the cheap honest version and it still looks right. Two field-set comparisons, no prose parsing:

1. **Every `### agentchat <command>` heading names a command the binary lists**, and every command the binary lists has a heading. That alone would have caught the missing `setup` section. Take the command list from the built binary's `--help`, not from a source constant, so the test fails when the document and the shipped tool disagree rather than when two source files do.
2. **Every fenced `json` example that is a single object has its key set compared** against the constant the corresponding shape is built from. `protocol-doc.test.ts` already exports several of these; reuse them rather than restating them.

## What it deliberately will not catch

A wrong *sentence* about a shape whose keys are right — which is exactly what the field-for-field claim was, and what the agent-name grammar was. Say so in the test's own module note, so the next reader does not mistake a green run for a correct document.

That limit is worth stating rather than designing around. A check that catches four of the five recurrences and says plainly which one it misses is worth more than one that pretends to read prose.

## Acceptance criteria

- [ ] The two comparisons above, in `packages/cli/tests/cli-doc.test.ts`, running in `pnpm test`.
- [ ] Each assertion made to fail deliberately before it is trusted: delete a heading, add one for a command that does not exist, and change a key in an example.
- [ ] The module note states what the check cannot see, in the register `protocol-doc.test.ts` uses for the same admission.
- [ ] No change to what `docs/cli.md` *says* beyond what the new checks force. This task builds the guard; the content was corrected in T-065.
