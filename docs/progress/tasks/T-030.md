# T-030 — Use the shared server resolver in the agent commands

There were three private copies of the server URL resolution. T-026 collapsed two of them into one shared function, and the third landed in the agent commands at almost the same moment, so `requireServerUrl` still lives privately in `packages/cli/src/commands/agent.ts`.

Both authors saw this coming and both made the right call at the time. The agent-commands task declined to promote the function because that meant editing two files another in-flight task owned, and the resolver task could not reach a file that did not exist when it started. Neither was wrong; the copy simply outlived the reason for it.

Two of the three copies had already drifted before being merged: one trimmed whitespace from the flag and reported no provenance, the other reported provenance and did not trim, so the same input was accepted by one and refused by the other. That is what this duplication does, and it took a review to notice.

## Acceptance criteria

- [ ] The agent commands call the shared resolver. The private copy is deleted, not aliased.
- [ ] Behaviour is unchanged where it was already correct, including the fresh-install failure message.
- [ ] The shared resolver's exports reach the package barrel. T-026 could not add them because that file was owned by another task, so the new functions are currently importable only by relative path.
- [ ] A test proves every command that talks to a server resolves it the same way, rather than testing each command separately. The point is that one function decides.

## Notes

Read the T-026 Log for the resolution order and for why this project deliberately ships no default server address.

If a fourth copy has appeared by the time you start, that is the argument for doing this now rather than after the remaining command tasks land.
