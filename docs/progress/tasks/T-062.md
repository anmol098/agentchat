# T-062 — The CLI reference quotes a protocol version the build no longer speaks

T-060 took `PROTOCOL_VERSION` to 4. `docs/cli.md` still prints `3` in three transcripts, including the `agentchat version --json` output a reader copies to test their own setup.

Found by T-060, which could not fix it: `docs/cli.md` was outside its declared paths and it reported rather than reached.

This is release-blocking in the narrow sense that the first published version would ship a reference contradicting its own binary on the very command whose job is to report the version.

## Acceptance criteria

- [ ] Every quoted `protocolVersion` matches `PROTOCOL_VERSION`.
- [ ] Check the agent-name grammar while you are there. T-060 narrowed it to `^[a-z0-9](?:[a-z0-9]|-(?=[a-z0-9])){0,31}$`, so any prose or example implying `agent-` is a valid name is now wrong.
- [ ] Verify against the built binary, not the source: `pnpm -r build && node packages/cli/dist/bin.js version --json`.
- [ ] Sweep for other version-shaped claims. This file has been found stale four times now, which is the argument for the check T-046 sketched and nobody has built.

## Notes

`docs/protocol.md` has a test that parses it and asserts it against live constants, and it has never gone stale. `docs/cli.md` has none. That asymmetry is the whole story of this task and of T-046 before it.
