# T-019 — Wire authentication into the running server

The device flow and the authentication plugin are both written, tested, and unreachable. Neither is called from `app.ts`, and the configuration layer reads none of the variables they need. Logging in does not work.

This gap exists because three tasks each correctly declined to edit files they did not own, and no task owned the wiring. That is the path-ownership rule working as intended right up to its blind spot: nobody is assigned the seam.

## What is missing

- `registerAuthRoutes` is never called, so the device-flow endpoints do not exist at runtime.
- `registerAuth` is never called, so nothing verifies a bearer token.
- `config.ts` does not read `JWT_SECRET`, which the token service needs, nor `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET`, which the provider needs.
- The token service is not injected into the auth routes. T-103 depends on a single method, `issueForUser`, and T-104 provides `issue`. Adapting one to the other is a small object literal at the wiring site, not a change to either module.

## Acceptance criteria

- [ ] Both are registered, and a real bearer token obtained through the device flow is accepted on a protected route.
- [ ] `JWT_SECRET` is required and validated at boot; a missing or too-short value fails fast with a message naming the variable. It must never appear in a log or an error.
- [ ] `GITHUB_CLIENT_ID` is required and non-empty; the provider throws on a blank one, so it should fail at boot rather than on first use. The secret must never appear in a configuration error message.
- [ ] `/healthz`, `/version` and the device-flow routes declare themselves public. Everything else is protected by omission, which is how T-105 made it fail closed.
- [ ] An integration test proves the whole path: unauthenticated request refused, device flow completed against a stubbed provider, the resulting token accepted.

## Notes

Read the Logs of T-103, T-104 and T-105 before starting. Each states precisely what it expects from the others, and between them the interface is already settled.

T-105 deliberately left `JWT_SECRET` out of `config.ts` because T-103 needed the same file and a concurrent edit would have collided. That reasoning was right; this task is where it lands.
