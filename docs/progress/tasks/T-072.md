# T-072 — The README reads like an internal specification rather than an introduction

The maintainer's verdict on the root README: it is technical and dense, and a reader does not come away knowing what the project is. It opens with the wire contract's guarantees, spends its first screen on stdout and stderr and the two JSON message shapes, and its quick start is a from-source server walkthrough with transcripts. All of that is true and all of it belongs somewhere; none of it is what a person landing on the repository needs first.

## Acceptance criteria

- [ ] The README answers three questions in order, in plain words: what this is and what problem it solves, what it looks like in use, and how to start. Everything else is a link.
- [ ] A reader who runs neither a server nor a build can follow the "start" section: install the CLI, log in to a server someone runs, set up, listen. Running a server points to the self-hosting manual; building from source points to the contributor guide.
- [ ] The from-source walkthrough (build, local PostgreSQL, migrate, start the server) moves to `CONTRIBUTING.md`, which already covers local setup and is where a contributor looks for it.
- [ ] No section sign, no em dashes, no decision or task identifiers, and no paragraph that explains a design choice a first-time reader has not yet met. Bold is used for at most one phrase per section.
- [ ] Every relative link resolves.

## Notes

The examples table, the concept table, the documentation table and the licence summary stay, shortened. The "what has been run" section goes: the quick start no longer contains transcripts to vouch for.
