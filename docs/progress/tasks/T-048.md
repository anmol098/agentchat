# T-048 — A dedicated close code for a socket closed for not reading

T-032 closes a socket whose peer has stopped reading, and closes it with `1000`. That is defensible: `1000`'s documented remedy is reconnect and take the replay, which is exactly right here, and the cause travels in the close frame's reason.

It is still the wrong code for one reader. A client collecting its own metrics cannot separate "the server restarted" from "I stopped reading my socket". Those have opposite fixes — one is somebody else's deploy, the other is a bug in the client's own event loop — and a reason string is prose, not a key.

T-032 did not mint one, correctly. `CloseCode` lives in `server/src/websocket/frames.ts`, outside its declared paths, and §9 forbids an agent minting a wire code unilaterally.

## Acceptance criteria

- [ ] Decide whether to add the code, argued the way T-017 argued the error set: would a client take a different action? If the answer is no, close this task with the argument written down rather than adding it.
- [ ] If added: an additive `CloseCode` member, a `CloseReason` factory beside `internalFailure`, one row in `docs/protocol.md` §9.6, and the change in `deliver()`. T-032's Log names all four.
- [ ] The close-code table is checked against the constant in both directions by `server/tests/protocol-doc.test.ts`. It will fail until the document is updated, which is the mechanism working.
- [ ] `pnpm protocol:check` must report the change as additive. Confirm rather than assume.
- [ ] A test asserting the code, and asserting that the message which tripped the bound is still replayed to the next connection.
