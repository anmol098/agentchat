# T-071 — A system design document in the repository, with the architecture and every flow drawn

The maintainer asked for one place that shows the whole system: the components and the licence line between them, the deployment, the data model, the flows for sign-in, context resolution, send and acknowledge, a listener's life, offline replay, upgrade and release, the state machines, and the interface tables. It was produced as a published page on 2026-09-12; it belongs in the repository so that every contributor and self-hoster finds it, and so that GitHub renders the diagrams where the source is.

## Acceptance criteria

- [x] `docs/system-design.md` with every diagram as a fenced `mermaid` block, which GitHub renders natively, and the specification tables transcribed from `docs/protocol.md`.
- [x] A section on what each identifier is for, in particular `sessionId` and `conversationId`, which the maintainer asked about.
- [x] Linked from the documents table in `README.md` and the reading table in `CLAUDE.md`.
- [x] Follows the naming and style rules in `CONTRIBUTING.md`: kebab-case file, no section sign, no references to task identifiers or decision numbers in the reader-facing text.

## Notes
