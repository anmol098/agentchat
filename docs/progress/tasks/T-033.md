# T-033 — Register the WebSocket endpoint on the application

The handshake handler, the socket registry and the router all exist, and none of them is reachable. Nothing in the application registers a WebSocket route, and the server has no WebSocket dependency, because the handshake was deliberately written against a structural interface so it needed none.

This is the fourth time this shape has appeared on this project, so it is being created before the work rather than discovered after it. The three previous instances were the authentication wiring, the CLI package barrel, and the milestone 1 routes; each time several tasks each needed one line in a file none owned, each correctly declined, and finished work sat unreachable.

## Acceptance criteria

- [ ] A WebSocket route exists, and a client can complete the handshake against a running server.
- [ ] Whatever dependency the adapter needs is added deliberately, with the licence check passing. The server is copyleft, so a copyleft dependency is acceptable here, but permissive is still preferable.
- [ ] The registry is held at the wiring site and given to the handshake through the observer hooks the handshake exposes. Nobody else may hold the registry.
- [ ] The router is closed on shutdown, in the right order relative to the HTTP server and the database pool.
- [ ] An integration test drives a real socket end to end: connect, authenticate, hand shake, receive, disconnect.

## Notes

Read the T-306 Log for the observer seam and the close codes, and the T-307 Log for the two lines it expects here and for what it says about shutdown.

Note the maximum frame size must match the HTTP body limit; T-306 imports it rather than restating it, and the adapter needs the same value.
