# T-008 — Board validation in continuous integration

Keeps the progress board trustworthy by failing the build when a task file is malformed, a dependency is unknown, two active tasks own overlapping paths, or the rendered board is stale.

## Acceptance criteria

- [x] `node scripts/board.mjs check` runs on every pull request.
- [x] A stale `BOARD.md` fails the check.
- [x] The failure message tells the contributor exactly which command to run.

## Notes

Protocol §1. The board is derived state; this job is what stops it drifting.

**Closed without a separate workflow.** T-004 put `board:check` in the `static` job, which satisfies the first criterion, and the validation the other two describe was already implemented in `scripts/board.mjs`. Building a second workflow to run the same command would have been duplication that drifts.

All three criteria were verified by hand at review: a stale board fails, and a task file missing its acceptance-criteria heading fails with a message naming the file and the problem.
