# T-104 — Token service with rotating refresh tokens

Issues short-lived access tokens and long-lived refresh tokens, rotating the refresh token on every use so a stolen one has a short useful life.

## Acceptance criteria

- [ ] Access tokens are signed JWTs with a one-hour expiry and the documented claims.
- [ ] Refresh tokens are random 32-byte values stored only as a SHA-256 hash.
- [ ] Refreshing rotates the token and revokes the previous one atomically.
- [ ] Reuse of an already-rotated refresh token revokes the whole chain and returns a distinct error code.
- [ ] Logout revokes the presented refresh token.
- [ ] Unit tests cover expiry, rotation, revocation, and the reuse-detection path.
